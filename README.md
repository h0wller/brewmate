# BrewMate ☕

PWA для кофейных энтузиастов и профессионалов: рецепты с таймером, профиль зерна, каппинг, BLE-весы и AI-рецепты по фото пачки. Интерфейс на русском, данные хранятся на устройстве.

## Возможности

- **Заваривание** — рецепты (доза, вода, температура, помол, шаги) и таймер со звуковыми сигналами; при подключённых весах прогресс шага считается по граммам.
- **Журнал** — запись о каждом заваривании с оценкой, зерном и заметками; с весами сохраняется кривая веса по времени, на графике она сравнивается с планом рецепта.
- **Кофемолка** — выбор своей модели из открытого каталога (CC0, формат CoffeeJSON) или своя; помол в рецептах хранится как уровень крупности + настройка на твоей кофемолке. Перевода «клики одной кофемолки → клики другой» нет сознательно: у моделей разные шкалы, поэтому соответствие уровней настройкам задаёшь ты (экран «Моя кофемолка»).
- **Зерно** — профиль зерна, прикидка обжарки (Agtron) по фото, рекомендации по помолу, температуре и пропорции, создание рецепта в один клик.
- **AI-рецепт** — фото пачки → профиль зерна и рецепт. Работает бесплатно и без настройки: фото уходит на сервер BrewMate (`api/vision`), который сам выбирает рабочий бесплатный сервис (Gemini, Groq, OpenRouter) и ограничивает число запросов в день. Продвинутые могут вписать свой ключ любой vision-модели с OpenAI-совместимым API (⚙️ → «AI: свой ключ») — тогда лимита нет, а запросы идут напрямую из браузера. Фото перед отправкой уменьшается до 1024 px.
- **Каппинг** — формы SCA и CoE, несколько лотов в сессии, дефекты, подсчёт баллов.
- **Весы** — Web Bluetooth, протокол FUTULA / LFSmart (вес, стабильность, единицы, tare). Работает в Chrome на Android; на iOS Web Bluetooth недоступен.
- **Обмен рецептами** — экспорт и импорт в открытом формате [CoffeeJSON](https://github.com/coffeejson-org/coffeejson) (⚙️ → «Рецепты в CoffeeJSON»): файл читают и другие приложения на этом стандарте. В таймер попадают шаги, у которых есть и время, и вес; рецепты по выходу (эспрессо) и шаги без воды пропускаются с пояснением.
- **Синхронизация** — опционально через Supabase по общему коду.
- **PWA** — устанавливается на домашний экран, таймер, рецепты и каппинг работают офлайн (интернет нужен только для AI и синхронизации).

## Стек

React 19 · TypeScript · Vite · vite-plugin-pwa · Supabase (синхронизация) · Oxlint

## Запуск

```bash
npm ci
npm run dev       # разработка
npm run build     # tsc + production-сборка
npm run lint      # oxlint
npm test          # юнит-тесты (vitest)
node scripts/import-coffeejson-gear.mjs <gear.json> <commit>   # обновить каталог кофемолок
npm run preview   # предпросмотр сборки
```

## Структура

```
src/
  App.tsx                 вкладки и общее состояние
  useBrewTimer.ts         логика таймера
  ScaleChip.tsx           UI весов
  bt/                     Web Bluetooth, интерфейс ScaleDriver и драйверы весов
  coffeejson/             экспорт и импорт рецептов в CoffeeJSON
  grinders/               каталог кофемолок, шкала крупности, профиль «моя кофемолка»
  beans/engine.ts         рекомендации и оценка обжарки по фото
  cupping/sca.ts          формулы SCA / CoE
  ai/                     клиент AI (сервер BrewMate или свой ключ), сжатие фото, запрос к модели
  sync/sync.ts            синхронизация через Supabase
  storage.ts              хранение в localStorage
```

## Бесплатный AI на сервере (Vercel)

Функция `api/vision.ts` держит ключи провайдеров и не показывает их браузеру. Настройка в Vercel → Settings → Environment Variables (полный список — в `.env.example`):

- хотя бы один из `GEMINI_API_KEY`, `GROQ_API_KEY`, `OPENROUTER_API_KEY` (ключ создаётся бесплатно в кабинете провайдера);
- по желанию `AI_LIMIT_PER_USER` (по умолчанию 10 запросов в сутки на человека) и `AI_LIMIT_GLOBAL` (500 на всех), чтобы бесплатные квоты не сгорели;
- по желанию Upstash Redis из Vercel Marketplace (`UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`): тогда счётчики общие для всех экземпляров функции. Без него лимиты считаются в памяти одного экземпляра и точны лишь приблизительно.

Сервер принимает только фото и название метода и сам строит запрос к модели, поэтому его нельзя использовать как бесплатный чат. Модель каждого провайдера можно сменить переменной `GEMINI_MODEL`, `GROQ_MODEL`, `OPENROUTER_MODEL` без обновления приложения. В `npm run dev` функции нет: для проверки AI запускай `vercel dev`.

Бесплатные тарифы провайдеров могут использовать присланные данные для улучшения своих продуктов, а Gemini free прямо делает это в обмен на бесплатный доступ: фото пачки уходит стороннему сервису.

## Синхронизация (Supabase)

Нужен проект Supabase с таблицей `sync` (`id text primary key`, `data jsonb`, `updated_at timestamptz`). URL проекта, anon key и общий код вводятся в приложении (⚙️ на экране рецептов). Перед использованием настрой RLS для таблицы.
